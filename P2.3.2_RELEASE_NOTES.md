# SmartQuote P2.3.2 — Product Semantics / Identity Separation

## Why
P2.3.1 fixed canonical SKU recovery but the catalog could still use a broad category as the product name. Example: a gate motor was shown as `Cổng tự động ...` even though the sellable item is the motor/opener.

## Identity model
P2.3.2 keeps these concepts separate:

- **Category** — broad catalog group, e.g. `Cổng tự động`
- **Product Type** — actual item being sold, e.g. `Động cơ cổng tự động`
- **Subtype** — engineering/commercial subtype, e.g. `Âm sàn`, `Cổng trượt`, `Tay đòn / mở xoay`
- **Commercial Model** — e.g. `VULCAN 24V`, `TORQ 500D`
- **SKU** — canonical product code, e.g. `29G020`, `30C109`
- **Canonical Name** — human-facing sellable product name

The full semantic identity is also persisted in `attributes.identity` so the source alias/name remains auditable.

## Bisco examples

| Source alias | Category | Product Type | Subtype | Model | SKU | Canonical Name |
|---|---|---|---|---|---|---|
| Vulcan - 24V (29G020) | Cổng tự động | Động cơ cổng tự động | Âm sàn | VULCAN 24V | 29G020 | Động cơ cổng tự động âm sàn VULCAN 24V |
| TORQ 500D | Cổng tự động | Động cơ cổng tự động | Cổng trượt | TORQ 500D | 30C109 | Động cơ cổng trượt tự động TORQ 500D |
| NYK - 24V | Cổng tự động | Động cơ cổng tự động | Tay đòn / mở xoay | NYK 24V | 29H001 | Động cơ cổng mở xoay tay đòn NYK 24V |

## Safety
- Category alone is **not** enough to rewrite an item as a motor.
- Semantic rewrite requires strong motor/opener evidence.
- Existing catalog rows created before P2.3.1 can be repaired during re-import only when stored evidence still contains an explicit labelled `Model/SKU/Code`.
- Raw source alias/name is preserved for audit.
- No Supabase migration is required; semantic fields are preserved in `raw_product` and `attributes.identity`.

## UI
Import preview now shows Category, Product Type, Subtype and Commercial Model below the canonical name. Manual row editing also exposes Model, Product Type and Subtype independently from SKU and Category.
