# SmartQuote P2.3 — Engineering Rules Foundation

Date: 2026-10-31
Base: SmartQuote P2.0 Learning Memory Foundation

## What changed

P2.3 adds a deterministic engineering-validation layer beside the existing Phase 15 Quote Completeness and P2.0 Learning Memory layers.

### New engineering engine

New module: `src/engineering/engineeringRules.js`

Implemented checks:

- CCTV NVR channel capacity
- NVR incoming-bandwidth capacity
- PoE usable-port capacity
- PoE power-budget capacity
- CCTV storage retention estimate
- Explicit product dependency rules
- Quantity dependency rules (`1 gateway per N devices` style)
- Explicit protocol compatibility checks
- Generic capacity-group support for non-CCTV domains

Every rule returns structured evidence with `PASS`, `FAIL`, or `UNKNOWN`.

`UNKNOWN` is deliberate: missing technical data never becomes a fabricated PASS.

## Product technical attributes

Catalog products can now store verified engineering data under:

```js
product.attributes.engineering
```

The Product Editor exposes fields for technical role, camera power/bitrate/PoE, NVR capacity, PoE switch capacity, storage capacity, protocols and explicit dependencies.

These fields are intended for verified datasheet/manufacturer information only.

## Quote Builder integration

The Quote Builder now includes an `Engineering checks` panel.

Project-level inputs currently supported:

- retention days
- default camera bitrate
- storage safety percentage

The panel shows actionable engineering issues and evidence without replacing Phase 15 historical/completeness suggestions.

## Final Quote safety

Engineering validation is captured in `quote.calc.engineeringValidation` when a quote is saved/finalized.

If deterministic engineering checks contain an `ERROR`:

- the user must either fix the configuration; or
- enter an override reason of at least 8 characters;
- Finalization then requires a second explicit confirmation;
- the override reason is frozen in the Final Quote snapshot.

A new revision clears the previous engineering override reason.

## Architecture rule preserved

P2.3 does **not** use quote-history frequency or LLM output as engineering truth.

- Phase 15 / P2.0: what users historically included or corrected.
- P2.3: deterministic constraints using verified technical attributes.

No Supabase schema migration is required for P2.3 v1 because product engineering attributes already fit the catalog JSON attributes field and engineering validation is stored in the existing quote `calc` JSON snapshot.

## New regression command

```bash
npm run smoke:pilot-p23
```

The main `smoke:pilot` chain now includes P2.3 before P2.0.
