# SmartQuote P2.3.6 RC6 — Identity & Provenance Hardening

## Why RC6 exists
RC5 reduced broad price/name corruption, but the 10-supplier Diagnostic v3 corpus still exposed four shared identity problems:

1. PDF code+description rows could still collapse `name = SKU` (NPP Bisco).
2. A shorter family/stem code from a later column could override the more specific source-leading variant code (`D001` vs `D001-TT`, `R1-001` vs `R1-001-CV`).
3. Inferred columns could promote feature/dimension/material tokens into SKU (`TAY/TH`, `IN/CHECK`, `86X86X45MM`, `SS304`).
4. Technical feature text could become the visible product name even when SKU + category/supplier context were stronger.

RC6 fixes those root causes without supplier-name-specific parser branches.

## Changes
- Records whether SKU mapping came from an explicit source header.
- Rejects unlabelled letter-only feature abbreviations as canonical SKU.
- Prefers source-leading, more-specific variant codes over shorter later-column stems/ranges.
- Normalizes spaced model suffixes such as `SBX202 - 5C0` before SKU tokenization.
- Rejects dimensions/material grades from free-text SKU extraction.
- Adds row-grounded commercial-name recovery for generic `Sản phẩm <SKU>` fallbacks.
- Prevents technical feature sentences from becoming product display names.
- No-SKU items keep the grounded source phrase instead of a synthetic `Sản phẩm - ...` prefix.
- Blocks percentage tax/total rows and debt/bank metadata earlier in extraction.
- Adds deterministic PDF raw-row name recovery for `SKU + description + unit + prices` layouts.
- Diagnostic v4 distinguishes exact visible duplicates from reviewable supplier-code collisions.

## Non-goals
- No OCR/vision work for scan-only Lighting/Smarthome PDFs.
- No forced SKU invention for products where the source genuinely provides no code.
- No supplier-specific hardcoded product list.
- No relaxation of Roger/Bisco golden gates.
