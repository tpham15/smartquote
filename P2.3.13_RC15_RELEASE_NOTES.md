# SmartQuote P2.3.13 RC15 — post-RC14 review hardening

Source of truth: `SmartQuote RC15 — Spec sửa lỗi sau review RC14.docx`.
RC15 changes only G1, F1, F2, F3 and T1. RC14 B1/B2/M1/M2 semantics remain in force.

## G1 — offline smoke assertions follow RC14 contract
- Engineering smoke now checks `Kiểm tra kỹ thuật` / `shouldShowEngineeringPanel(...)`, not removed internal copy.
- P1.5.3.1 finalization smoke reads root `01_RUN_ON_SUPABASE.sql`, the sole deployment SQL entry point.
- `smoke:pilot-p23.13` scans literal `readFileSync(path.join(root,...))` targets and fails if a fixed file path no longer exists.

## F1 — Final sales status is persisted by verified RPC
- Added `public.set_quote_sales_status(uuid,text)` in `supabase/phase23_13_quote_status_rpc.sql`, `schema.sql`, and root master SQL.
- RPC validates auth, allowed status and workspace membership, updates only `status` + audit fields, and returns the stored status.
- Client no longer performs a direct `quotes.update(...)`; it calls the RPC and rejects a mismatched/empty response.
- UI restores the previous dropdown value on RPC failure and shows success only after server confirmation.
- `smoke:pilot-p23.13` statically scans all `src/**/*.{js,jsx,mjs}` for forbidden direct quote-table updates.

## F2 — price-change warnings compare like-for-like
- `priceColumnRole=list` compares incoming list/public price with existing list/public price only.
- `price_column_uncertain` remains a required file-level decision and cannot be cleared by generic per-row approval/edit.
- New issues: `list_price_change_outlier`, `list_price_change_extreme`, `list_below_existing_cost`.
- `cost` / unconfirmed role retains existing cost-price comparison.
- Choosing/changing price role removes stale role-sensitive business issues and reruns shared catalog matching + commercial validation.

## F3 — preview, validation, count and save share one matcher
- Added `buildCatalogMatchIndex` / `resolveCatalogMatch` and production save helper `mergeCatalogImport`.
- Same matcher drives commercial validation, preview row label, projected catalog count and actual merge.
- Supplier guessed only from filename is marked `supplierSource=file_name`, ignored as hard identity evidence, and never overwrites an empty supplier on an existing product.
- Unresolved same-SKU matches are fail-closed as `catalog_match_ambiguous`; user must explicitly choose Update target or Add new. Generic approve/edit flags cannot bypass this decision.
- Every row in one import batch is matched against the same pre-import catalog snapshot, so first-time supplier-code reuse (Roger `FU`) is not turned into an artificial ambiguity by rows added earlier in the same batch.
- Catalog shows a yellow warning/filter for legacy duplicate SKU + same-name groups; no automatic destructive dedupe.
- Bisco real-file gate now uses the production RC15 merge helper for the re-import/repair assertion.

## T1 — smoke inventory is exact
- `smoke:all` counts SKIPPED only when a successful child emits a line beginning exactly `SKIPPED `.
- `smoke:pilot` and `smoke:pilot-release` are explicitly listed as staging-only skips; `smoke:pilot:offline` remains part of inventory.
- Vite `?url` Node hook is registered through `node:module.register`.
- Stale UX/design/upgrade/phase14 assertions were updated rather than silently deleted.
- Private phase12.5.3 fixture emits a concrete SKIPPED reason when absent.
