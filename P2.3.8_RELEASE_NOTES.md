# P2.3.8 RC10 — Final Supplier Identity Hardening

## Scope

RC10 is intentionally narrow. It targets the two remaining structured supplier files that were still FAIL in Diagnostic v4:

- MX-BG Tổng Hợp T062026
- NGUYÊN ĐÀ

No new product feature is introduced.

## Changes

1. **Late grounded identity recovery**
   - Recovers a commercial series from repeated-SKU rows such as:
     - `PA091 3 PLAIN PA091 ...` → `PLAIN PA091`
     - `CT701 6 CUTIE CT701 ...` → `CUTIE CT701`
   - Recovers a trailing sellable product block shaped as:
     `Unit | Qty | Commercial name/model | Brand/Origin | Prices`.
   - This fixes Aiphone-style rows where component models appear earlier than the actual sellable kit:
     - `JO-1MDW ... Bộ 1 Chuông cửa có hình JOS-1AW ...` → SKU `JOS-1AW`, name `Chuông cửa có hình JOS-1AW`
     - `JOS-1A ... Cái 1 Màn hình chính JO-1MDW ...` → SKU `JO-1MDW`, name `Màn hình chính JO-1MDW`
   - Long description rows keep a concise grounded leading label before the SKU.

2. **Missing-SKU tail recovery**
   - A product with a good name but no SKU may recover a code from the same grounded trailing sellable block.
   - Example: `Loa mở rộng ... Cái 1 Loa mở rộng IER-2 ...` → SKU `IER-2`.

3. **List-price-only scoring**
   - `scoreConfidence` no longer rejects a row solely because cost price and SKU are missing when a valid list/sell price exists.
   - Such rows remain reviewable instead of becoming FAILED.

4. **Resolved issue cleanup**
   - Removes stale early-stage issues after grounded recovery proves the field is now valid:
     - `missing_sku`
     - `missing_price`
     - `missing_cost_price`
     - `missing_product_name`
     - `generic_product_name`
     - `no_price_no_sku`

## Safety

Recovery runs only when identity is still generic/code-only or SKU is missing. It uses visible source-row evidence and does not invent a commercial name.

Golden Bisco/Roger logic, PDF geometry, quote lifecycle, security, billing, tenant isolation and engineering rules are unchanged.
