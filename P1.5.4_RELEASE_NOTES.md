# SmartQuote P1.5.4 — P0 Identity Safety Hardening

This release fixes the P0 identity-integrity issues found after P1.5.3.2.

## Fixed P0 issues

1. **Same SKU across different suppliers/brands no longer auto-matches or merges.**
   - Exact SKU matching is supplier/brand-aware.
   - Ambiguous duplicate SKU fails closed (`ambiguous_sku`).
   - Conflicting rows are preserved for review instead of last-row-wins.

2. **`Tên sản phẩm` always outranks `Hạng mục`.**
   - Column order no longer lets a left-side section column become product name.
   - `Hạng mục` remains a fallback name for service-only quote tables with no explicit product-name column.

3. **Technical variants are preserved.**
   - Short identity-bearing specs such as 12W/18W, 3000K/4000K, 2.8mm/3.6mm are not stripped from names as generic specs.
   - No-SKU dedupe includes technical variant signature.

4. **Manual mapping no longer synthesizes `category + SKU`.**
   - Commercial name is recovered from Specs when available.
   - Otherwise the neutral fallback is `Sản phẩm <SKU>` rather than using category as identity.

5. **Multi-file import no longer uses bare-SKU last-file-wins.**
   - Both adapter and mixed Excel/PDF batch paths use canonical identity dedupe.
   - Identity conflicts remain separate and are marked for review.

6. **Supplier price update fails closed on duplicate SKU.**
   - If a price-list SKU matches multiple catalog products and exact name cannot disambiguate, no product price is updated automatically.
   - UI shows the ambiguous SKU and candidate products for review.

## No database migration

P1.5.4 changes application/import identity logic only. No new Supabase SQL is required beyond the existing P1.5.3.1 pilot master migration.

## Pilot rule

When identity evidence conflicts, SmartQuote prefers **extra review/duplicate candidate** over silently merging or overwriting a product.
