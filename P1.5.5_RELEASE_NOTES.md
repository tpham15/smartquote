# SmartQuote P1.5.5 — P1 Identity Learning Safety

P1.5.5 completes the next identity-safety layer after P1.5.4. The goal is not to increase automatic matching; it is to make matching and learning safer when suppliers, brands and technical variants overlap.

## Fixed P1 issues

1. **Technical variants no longer fuzzy-match across conflicting specs.**
   - Fuzzy matching compares a conservative technical-variant signature.
   - Examples that now fail closed: `3000K` vs `4000K`, `2.8mm` vs `3.6mm`, `12W` vs `18W`, differing IP/voltage/current/channel/storage tokens.
   - If technical evidence is missing on one side, SmartQuote does not use fuzzy identity to bridge the gap.

2. **Exact SKU evidence now outranks stale correction memory.**
   - Match order is now: exact supplier/brand-aware SKU → validated correction → exact name → variant-safe fuzzy.
   - A correction is rejected if SKU, supplier/brand evidence or technical variant conflicts with the current row.

3. **Correction learning is supplier/brand scoped.**
   - Learning keys use `supplier/brand + canonical SKU`, not bare SKU.
   - Raw-text learning is scoped by the same party evidence.
   - Rows with no supplier/brand evidence do not create reusable identity memory; SmartQuote prefers no learning over unsafe cross-supplier learning.
   - P1.5.5 intentionally starts a new learning store (`sq_correction_learning_v2`) instead of migrating the old unsafe plain-SKU memory.

4. **Supplier, brand and origin are separate concepts end-to-end.**
   - `Nhà cung cấp/NCC` → `supplier`.
   - `Hãng/Thương hiệu/Brand/NSX` → `brand`.
   - `Xuất xứ/Origin` → `origin`.
   - Excel, PDF, manual/legacy import and AI mapping prompts all use the same separation.

5. **Quote export preserves origin semantics.**
   - Default Excel `Xuất xứ` exports `origin` first, with supplier only as a legacy fallback for old catalog rows.
   - PDF/template label `Xuất xứ` renders origin; `Hãng` renders brand; supplier labels render supplier.
   - Lossless Excel template detection distinguishes supplier/brand/origin and ignores stale old mappings that try to claim an `Xuất xứ` column as supplier.

## No database migration

P1.5.5 changes application/import/export/learning logic only. No new Supabase SQL is required beyond the existing P1.5.3.1 pilot master SQL.

## Pilot behavior

P1.5.5 remains deliberately fail-safe: conflicting or incomplete identity evidence creates review/no-match rather than silently changing product identity.
