# SmartQuote P2.3.1 — Product Identity Canonicalization

## Why
The Bisco old-quotation importer could still show a mixed alias such as:

- Product: `Cổng tự động Vulcan-24V (29G020)`
- SKU: `Vulcan-24V (29G020)`

That is not a stable product identity. The quote description contains stronger structured evidence: `Model: 29G020`.

## Fix
- In old-quotation mode, an explicitly labelled `Model`, `SKU`, `Code`, or `Mã SP` inside the product description outranks a mixed alias from the mapped quotation code column.
- Keeps commercial product name separate from canonical SKU.
- Recovers the commercial first line when an earlier fallback generated `category + alias` as the display name.
- Preserves the raw mapped code in import provenance instead of using it as canonical identity.
- Extends SKU extraction to numeric-prefix manufacturer codes such as `29G020`, `30C074`, `22F005`.
- Rejects technical values such as `230V`, `24V`, and `50HZ` as SKU candidates.
- Applies the same canonicalization safety net in the sanitizer for old-quote Excel/PDF/manual-mapping paths.
- Learning cannot overwrite the recovered canonical SKU because identity is resolved before learning and learned SKU only fills an empty SKU.
